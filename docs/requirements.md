# 1 引言

## 1.1 编写目的

本文档定义「接力（Relay）· 跨 Agent 的项目记忆与交接工作台」v1.0 的软件需求，作为后续软件设计、编码实现、测试与验收的共同基线。

预期读者包括：课程指导教师、项目开发者、测试人员，以及同时使用多个 coding agent 的开发者。本文档说明系统要解决的问题、功能边界、非功能约束、系统模型与验收标准；不规定具体的类结构、接口实现与界面代码，这些内容在《软件设计模型》中给出。

按照课程要求，2026-11-20 提交本文档后，系统的**核心范围**不再变更；后续允许修正文字、补充细节和调整非核心需求，但不得改变本文档确定的核心功能与系统边界。

## 1.2 适用范围

本文档适用于 Relay v1.0 本地单机桌面应用，覆盖以下范围：

- 工作区的注册、识别与项目档案管理；
- 多来源会话日志的发现、解析、脱敏与统一事件建模；
- 跨 agent 的使用统计与项目时间线；
- 习惯、环境与任务上下文的证据化提取、人工审核与版本化；
- 交接简报的生成、写入（AGENTS.md / CLAUDE.md / HANDOFF.md）与认领记录；
- 本地隐私、数据删除与脱敏导出。

本文档与以下制品相关：3.4 节的系统模型、后续的《软件设计模型》《测试》文档以及项目代码。本文档**不适用**于：云端多用户服务、协议网关（ACP/MCP/A2A 的实现）、agent 运行时、对代码语义的理解与分析、对开发者个人的绩效评价。

# 2 目前系统

## 2.1 现有工作流

同一个项目目录通常会在不同时间被不同的 coding agent 使用：先用 Qoder 完成需求与原型，再换 Claude Code 修构建脚本，之后用 Antigravity 或 Codex 继续实现。工作区文件是共享的，但**会话是各自私有的**：每个 agent 在自己的进程内维护上下文，会话结束后，决策理由、失败尝试、环境配置与人工纠偏都只留在该 agent 的日志里。

开发者目前依赖三种手工方式弥补：

- 在会话之间复制粘贴关键结论；
- 手工维护 CLAUDE.md、AGENTS.md、Cursor rules 等文件；
- 依赖记忆或聊天记录回溯「上次为什么这么做」。

这些方式都存在明显缺陷：复制粘贴不可持续；手工文件容易过期；聊天记录难以检索，且无法证明结论来自哪次修改。

## 2.2 现有方案

### 2.2.1 协议层

[[TABLE:表 2-1 协议层的覆盖与空白]]
| 方案 | 解决的问题 | 不解决的问题 |
|---|---|---|
| ACP（Agent Client Protocol） | 标准化编辑器/IDE 与 coding agent 之间的通信；任意编辑器连接任意 agent；会话创建、提示、权限、流式更新 | 会话是 agent 私有的；session/load、resume 只在同一 agent 内恢复；没有跨 agent 的会话迁移或项目记忆 |
| MCP | agent 调用工具与数据源 | 不管理会话、记忆与交接；需要 agent 或客户端实现 MCP |
| A2A | 独立 agent 之间的任务委派与协作 | 面向任务协作，不解决本地工作区的历史上下文沉淀；需要双方实现协议 |

ACP 的一个重要设计事实是：它把上下文建模为 Session，并把 Session 的恢复能力留在 agent 内部。即使多个 agent 都支持 ACP，开发者在另一个 agent 中新建会话时，仍然拿不到前一个 agent 会话中的决策、失败尝试与纠偏。ACP 统一的是「接线」，不是「交接」。

### 2.2.2 产品层

[[TABLE:表 2-2 现有工具的覆盖与空白]]
| 方案 | 覆盖能力 | 空白 |
|---|---|---|
| claude-mem | 捕获会话、AI 压缩、跨会话注入 | 依赖模型生成摘要，黑盒、不可回放；无环境档案与版本审核 |
| ai-memory | 跨 agent 交接简报，默认不使用 LLM | 协议/CLI 优先，缺少桌面端的审核、版本与档案体验 |
| PROJECTMEM | 事件溯源记忆、失败尝试警告、行动前门禁 | 偏研究原型；无习惯与环境档案，无图形化审核 |
| Continuity 等 MCP 记忆服务 | 结构化交接、可替换 agent | 要求 agent 支持 MCP；无版本化档案 |
| atlas | 汇总 CLAUDE.md、AGENTS.md、记忆文件的索引 | 只做索引与检索，不从原始日志提炼 |
| CC Switch | 多 CLI 的供应商配置、MCP/Skills 管理与用量统计 | 管理配置与用量，不管理项目经验与交接 |
| Command Code taste | 在 agent 内学习编码品味、单向导入 | 绑定自有 agent 生态，档案不可携带 |

## 2.3 问题总结

[[TABLE:表 2-3 问题归纳]]
| 编号 | 问题 | 影响 |
|---|---|---|
| P1 | 会话孤岛 | 换 agent 等于重新自我介绍，重复解释背景与约束 |
| P2 | 关键信息只存活在对话里 | 决策理由、失败尝试、纠偏、环境配置不进入项目资产 |
| P3 | 记忆不可迁移 | CLAUDE.md、Qoder 记忆、Cursor rules 各管各的，换工具就丢 |
| P4 | 现有记忆工具不可审计 | 模型摘要不可回放、不可人工确认，难以在课程/团队中建立信任 |
| P5 | 配置管理不等于经验管理 | CC Switch 类工具管配置与用量，不管「我怎么做这个项目」 |
| P6 | 协议方案的采用成本 | ACP/MCP 要求 agent 或客户端实现协议；未实现的工具不在网里 |

## 2.4 定位与机会

接力采用与协议方案相反的策略：**不要求任何 agent 适配，只在协议之外做三件事**。

[[TABLE:表 2-4 三个整合面]]
| 整合面 | 做法 | 依赖 |
|---|---|---|
| 读痕迹 | 只读解析本地会话日志，通过适配器转换为统一事件 | 只需文件系统读权限 |
| 写文件 | 把审核后的档案写入 AGENTS.md / CLAUDE.md / HANDOFF.md 的受管块 | 只需文件系统写权限 |
| 看事件 | 监听工作区、git 提交与会话结束，主动生成草稿与提醒 | 只需文件系统与 git 元数据 |

由此形成三条功能主线：

[[TABLE:表 2-5 三条功能主线]]
| 主线 | 内容 | 价值 |
|---|---|---|
| 使用统计 | 跨 agent、跨项目、跨时间的会话、工具、纠偏、交接统计 | 让开发者看清自己如何与多个 agent 协作 |
| 经验总结与注入 | 从证据中提炼习惯、环境与任务上下文，人工审核后写入 agent 原生文件 | 把一次性对话变成可复用资产 |
| 跨 agent 交接 | 生成有界交接简报，写入工作区，记录认领 | 换 agent 不丢上下文 |

# 3 需求

## 3.1 概述

### 3.1.1 系统目标

Relay v1.0 的目标是：

- **G1 捕获**：在不修改任何 agent 的前提下，读取本地会话日志并建立统一事件模型；
- **G2 提炼**：用可解释的规则与统计，从事件中提炼习惯、环境与任务上下文，并给出证据与置信度；
- **G3 交接**：把审核后的内容生成有界简报，写入工作区标准文件，让下一个 agent 进目录即读；
- **G4 统计**：提供跨 agent 的使用统计，支撑复盘与课程报告；
- **G5 治理**：全部本地处理，导入前脱敏，支持按项目删除与脱敏导出。

### 3.1.2 成功标准

- 首次使用 5 分钟内完成「注册工作区 → 导入 → 查看候选」；
- 每一条进入档案的条目都能回放到原始会话片段；
- 生成并写入交接简报不超过 3 次点击，写入前必须展示 diff；
- 连续两次生成相同档案时，工作区文件内容保持不变（幂等）；
- 整个流程不产生任何网络请求。

### 3.1.3 系统边界

[[FIG:../build/diagrams/context-relay.png|图 3-1 系统边界与外部依赖|16]]

系统以内为 Relay 工作台；系统以外为各 agent 的日志目录、工作区文件、git 元数据。Relay 不启动、不控制、不注入任何 agent；它只读取日志、写入工作区文件。

### 3.1.4 用户角色

[[TABLE:表 3-1 用户角色]]
| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 开发者（主用户） | 同时使用多个 coding agent 的开发者/学生 | 换 agent 不丢上下文；沉淀习惯与环境；复盘使用情况 |
| 审核者 | 通常是开发者本人 | 逐条确认候选、改写表述、合并重复项 |
| 目标 agent | Antigravity、Claude Code、Codex、Qoder 等 | 被动读取工作区文件；不感知 Relay 的存在 |
| 外部系统 | 文件系统、git | 提供日志、工作区文件与提交元数据 |

### 3.1.5 设计原则

- **零协议**：不要求 agent 支持 ACP/MCP/A2A，不安装插件；
- **证据优先**：任何结论都必须可回放到原文，人工确认后才进入档案；
- **主动但不越权**：自动发现与起草，但写入前给出 diff，默认不自动改配置；
- **本地优先**：日志与档案不出机器，不调用任何模型；
- **可带走**：档案版本化，可导出为通用格式，不绑定单一 agent。

### 3.2.2 主线一：使用统计

#### FR-18 使用统计看板

系统应提供跨 agent、项目与时间的统计视图，帮助开发者理解协作过程。所有指标必须由事件库直接计算，不得估算。

[[TABLE:表 3-3 统计指标]]
| 指标 | 定义 | 维度 |
|---|---|---|
| 会话数 | 已导入的去重会话数量 | agent、项目、时间 |
| 轮次数 | 用户与 assistant 的交互轮次 | agent、项目、时间 |
| 工具调用数 | tool_use 事件数量，按工具名分组 | agent、工具、时间 |
| 工具失败率 | 失败 tool_result / tool_use 总数 | agent、工具 |
| 纠偏次数 | Correction 事件数量 | agent、项目、类别 |
| 编辑文件数 | 有 Edit 事件的去重文件路径数 | agent、项目 |
| 交接次数 | 已生成的交接简报数量与已认领数量 | 目标 agent、时间 |
| 档案条目数 | 按状态（候选/已接受/已归档）统计 | 类别、作用域 |

**规则**：

- 时间范围支持最近 7/30/90 天与全部；
- 会话按稳定 ID 去重；跨源不合并同名会话；
- 统计页需标注数据来源与最近刷新时间；
- 空数据显示空状态说明，不显示虚构数据。

**验收**：对固定夹具运行统计，结果与事件库查询一致；切换筛选条件时数字联动；导出 CSV 可用（P1）。

#### FR-08 时间线与证据浏览

系统应把同一工作区内多个 agent 的会话合并为一条项目时间线，并允许从任意事件跳转到原始日志片段。

- 支持按 agent、时间、事件类型筛选；
- 工具调用、文件编辑、纠偏以不同样式区分；
- 点击证据打开原文预览，显示文件、行号、时间戳与会话 ID；
- 原文预览只读，不复制整份日志入库。

**验收**：给定两个来源的夹具，时间线按时间正确合并；证据定位与原始文件一致；筛选结果可复现。

### 3.2.3 主线二：经验总结与注入

#### FR-09 纠偏事件提取

系统应从会话中识别「用户纠正 AI」的事件，作为习惯与任务上下文的高价值信号。

**识别规则（可配置）**：

- 用户消息紧随 assistant 输出，且包含否定、修正或明确偏好表达；
- 同一文件在短时间内被多次修改，且中间存在用户指令；
- 工具失败后，用户给出不同的做法；
- AskUserQuestion 的选项与自由输入被用户选择/改写。

**输出**：Correction 事件，包含原文、证据、类别（风格/命令/依赖/流程/其他）、置信度。

**验收**：纠偏夹具的召回与误报在可接受范围；每条纠偏可回放到原文；规则可开关。

#### FR-10 习惯候选提取

系统应从事件中提炼稳定的工程习惯，生成带证据的候选条目。

[[TABLE:表 3-4 习惯分类与信号]]
| 类别 | 典型信号 | 示例 |
|---|---|---|
| 命令与包管理 | 高频成功命令、用户明确指定 | 优先 pnpm；测试命令 pnpm test |
| 命名与风格 | 用户纠正命名、重复出现的命名模式 | 组件用 PascalCase；文件名用 kebab-case |
| 依赖与工具选择 | 安装/卸载、失败后切换 | 桌面端用 Electron，不用系统 WebView |
| 目录结构 | 文件创建路径的重复模式 | 文档放 docs/；脚本放 scripts/ |
| 测试与文档 | 测试命令、文档文件、注释语言 | 提交前跑全量测试；注释用中文 |
| 注释与语言 | 用户对语言的偏好 | 代码标识符英文，界面文案中文 |
| 禁用项 | 明确的「不要/不要用」 | 不在日志写真实姓名与学号 |
| 发布流程 | 打包、版本、产物命名 | 产物名保留版本号与空格 |

**候选生成规则**：

- 同一陈述在多个会话中重复出现，或由一次明确的用户纠正支撑；
- 每条候选包含：陈述、类别、证据列表、证据数、置信度、作用域（全局/项目）、首次/最近出现时间；
- 语义相近的候选去重；同一类别出现矛盾时标记冲突，交人工处理；
- 候选不直接进入档案，必须经 FR-13 审核。

**验收**：黄金夹具生成预期候选；置信度随证据数单调变化；冲突被标记而非自动合并。

#### FR-11 环境事实提取

系统应从会话中提炼可复现的环境事实：

- 工具链与版本（如 Node 24、Python 3.12、pnpm 9）；
- 常用命令与工作目录；
- 路径约定（项目根、构建输出目录、缓存目录）；
- 网络与代理配置（仅记录是否存在与形式，不记录密钥）；
- 外部依赖与本地服务。

环境事实必须来自工具调用与输出，或用户明确陈述；不得根据文件名猜测。重复出现的事实提升置信度。

**验收**：夹具中的版本与命令被正确抽取；密钥不会被记录；用户可编辑与删除。

#### FR-12 任务状态提取

系统应从最近会话中提炼交接所需的任务上下文：

- **目标**：最近一次明确的任务陈述；
- **当前状态**：已完成、进行中、被阻塞；
- **已确认决策**：含理由的技术/产品决策；
- **失败尝试**：工具失败、被放弃的方案、用户明确说「不要」的路径；
- **待决问题**：未回答的问题与开放选择；
- **下一步**：明确的后续动作或 TODO。

**验收**：给定会话夹具，简报字段可生成且可编辑；失败尝试不与普通错误混淆。

#### FR-13 候选审核

系统应提供收件箱式审核界面：

- 按类别、置信度、来源 agent 筛选；
- 每条候选展示陈述、证据数、置信度、证据原文；
- 支持接受、改写、合并、忽略；
- 批量操作需二次确认；
- 审核记录写入审计日志，可追溯谁在何时改了什么。

**验收**：审核后条目进入档案；忽略的候选不再出现；审计日志完整。

#### FR-14 档案版本管理

系统应对档案进行版本化：

- 每次接受的变更生成新版本；
- 支持查看两个版本之间的 diff；
- 支持回滚到历史版本；
- 作用域分为全局与项目；同一陈述在不同作用域可共存；
- 版本记录包含时间、来源审核操作与变更摘要。

**验收**：连续接受两条候选后生成 v2，diff 正确；回滚后内容与历史一致。

#### FR-16 写入与注入

系统应把档案注入 agent 可读的原生文件，并提供复制方式。

[[TABLE:表 3-5 注入目标]]
| 目标 | 文件 | 说明 |
|---|---|---|
| Antigravity / Codex / 通用 | AGENTS.md | 使用受管块写入习惯与环境 |
| Claude Code | CLAUDE.md | 同上；可只写项目级 |
| 交接 | HANDOFF.md | 写入任务状态与交接简报 |
| 归档/交换 | JSON | 完整档案导出，含版本与证据引用 |

**受管块规则**：

- 使用固定标记包围，例如 `<!-- relay:begin habits -->` 与 `<!-- relay:end habits -->`；
- 只替换标记内的内容，标记外内容原样保留；
- 写入前展示 diff，用户确认后原子写入；
- 连续两次写入相同档案时文件内容不变（幂等）；
- 若用户在受管块内手工修改过内容，检测到哈希不一致时提示冲突，由用户选择覆盖或保留。

**注入方式**：

- 默认：写入文件 + 一键复制简报文本；
- P1：在用户开启后，档案变更时提示更新（仍需确认），不自动静默写入；
- 不实现：自动向运行中的 agent 注入、自动修改 agent 配置。

**验收**：黄金文件测试覆盖 AGENTS.md、CLAUDE.md、HANDOFF.md；幂等测试通过；冲突提示可复现；写入失败不破坏原文件。

#### FR-20 数据管理与隐私

系统应提供：

- 数据目录说明与打开入口；
- 按项目删除全部事件与档案；
- 全量删除与导出；
- 脱敏开关与规则编辑；
- 导出时可选「脱敏副本」。

**验收**：删除后相关查询为空；导出不包含密钥与真实邮箱；删除操作需二次确认。

### 3.2.4 主线三：跨 agent 交接

#### FR-15 交接简报生成

系统应根据所选字段生成有界交接简报：

[[TABLE:表 3-6 交接简报字段]]
| 字段 | 内容 | 必选 |
|---|---|---|
| 当前任务 | 目标与范围 | 是 |
| 当前状态 | 已完成/进行中/被阻塞 | 是 |
| 已确认决策 | 决策与理由 | 是 |
| 失败尝试 | 已放弃路径与原因，标注「不要重复」 | 是 |
| 下一步 | 明确的后续动作 | 是 |
| 环境 | 工具链、命令、路径、代理 | 是 |
| 待决问题 | 未回答的问题 | 否 |
| 文件热点 | 最近修改的关键文件 | 否 |

**规则**：

- 简报长度设上限（默认 1,500 token / 120 行），超出时提示裁剪；
- 按稳定顺序输出，避免无意义 diff；
- 不包含密钥、真实邮箱、绝对用户路径（可配置保留）；
- 生成后进入预览，允许手工编辑，再写入。

**验收**：黄金简报测试；字段可勾选；超长提示；脱敏生效。

#### FR-17 交接认领与历史

系统应记录交接的生命周期：

[[TABLE:表 3-7 交接状态]]
| 状态 | 含义 | 触发 |
|---|---|---|
| Draft | 正在编辑 | 打开交接界面 |
| Previewed | 已预览未写入 | 生成预览 |
| Written | 已写入工作区 | 确认写入 |
| Claimed | 已被新的 agent 会话读取/使用 | 检测到工作区新会话或手工认领 |
| Acknowledged | 接手方确认收到（P1） | 目标 agent 会话出现或手工确认 |
| Outcome | 记录接手后的结果（P1） | 用户/检测记录完成、失败或部分完成 |
| Archived | 已归档 | 用户归档或超过保留期 |

- 每条交接有稳定 ID；
- claim-once：同一交接只允许认领一次；
- 认领检测优先使用工作区新会话事件，无法检测时提供手工按钮；
- 历史列表展示生成时间、目标 agent、状态与文件位置。

**验收**：状态转换正确；重复认领被拒绝；历史可筛选。

### 3.2.5 支撑层：Agent 台账与资产索引

#### FR-21 Agent 台账与兼容矩阵

系统应维护一份只读的 Agent 台账：

- 记录已识别 agent 的安装状态、日志路径与格式、hook 能力、MCP 配置、skills 目录、rules/memory 文件；
- 形成兼容矩阵：能否读取 AGENTS.md / CLAUDE.md、是否支持 hooks、是否支持 MCP、能否续跑会话；
- 提供健康检查（目录可读、最近会话时间、格式指纹）；
- 台账只读，不修改任何 agent 配置。

**验收**：至少识别 Qoder 与 Antigravity；未知 agent 可手工登记；兼容矩阵能驱动注入方式选择。

#### FR-22 资产索引与导出（P1）

- 索引 skills、MCP、prompts、hooks 的路径、版本、哈希与最近修改；
- 同名不同内容标记 drift；
- 支持把「内容」导出/投影到目标 agent 的格式；
- 不自动安装、不执行任何 hook 或脚本。

**验收**：夹具目录可索引；drift 可复现；导出不覆盖用户内容。

### 3.2.6 主线三扩展：任务与派工

#### FR-23 任务与派工

系统应把「任务」作为一等实体：

- 字段：工作区、目标、状态、当前 owner agent、关联会话、已确认决策、失败尝试、下一步、验收条件、产出物；
- 提供派工流程：选工作区 → 选任务 → 选目标 agent（依据 FR-21 的兼容矩阵）→ 预览上下文包 → 选择注入方式 → 确认 → 记录 Claim；
- 上下文包包含任务简报、长期规则、失败警告、文件热点、环境与「先读这些文件」指针；
- P0 任务手工创建或从最近会话选择；P1 支持从会话自动建议任务；
- 不控制 agent 运行时，不并行调度多个 agent。

**验收**：同一任务可在 Qoder 与夹具 agent 之间交接；上下文包字段完整且有界；Claim 只发生一次。

### 3.2.7 接入与导入

#### FR-01 工作区注册与管理

- 用户选择本地目录注册工作区；
- 识别 git 仓库（远程地址、分支）与项目名称；
- 工作区移动后可通过重新定位恢复关联；
- 支持重扫、暂停监听与删除。

**验收**：注册后显示项目身份；非 git 目录也可用；路径变更后可恢复。

#### FR-02 适配器框架

[[TABLE:表 3-8 适配器契约]]
| 能力 | 说明 |
|---|---|
| discover | 在给定根目录下发现日志源 |
| fingerprint | 识别格式与版本，记录指纹 |
| parse | 从游标开始增量解析，返回事件与下一游标 |
| capabilities | 声明是否支持工具调用、编辑、纠偏、用量等 |
| fixtures | 提供夹具与一致性测试 |

要求：适配器相互隔离，单个适配器失败不影响其他；未知事件类型保留为 UnknownEvent；格式变化时降级并提示，不崩溃。

**验收**：注册三个适配器，其中一个故意抛错，其余仍能工作。

#### FR-03 Qoder 日志适配

支持解析 Qoder 会话 JSONL：

- 会话元信息：sessionId、目录、模型、时间戳；
- 消息：user、assistant、thinking、tool_use、tool_result；
- 工具名与参数（Bash、Read、Edit、WebSearch 等）；
- 文件编辑与时间戳；
- 增量读取与重复行去重。

**验收**：使用真实会话验证事件数与工具统计；重复导入不产生重复事件。

#### FR-04 Antigravity 摘要适配

支持读取 Antigravity 的会话摘要数据库：

- 会话标题、步数、工作区、状态、来源、父会话与嵌套深度；
- 仅作为索引与时间线补充，不声称拥有完整对话；
- 界面明确标注「摘要来源」。

**验收**：摘要正确显示；无完整内容时不出现虚假证据。

#### FR-05 Claude Code 夹具适配

按公开的 JSONL 会话格式实现解析，并提供夹具：

- 用于测试与演示，不声称读取本机真实 Claude Code 数据；
- 夹具覆盖普通对话、工具调用、编辑与纠偏；
- 在界面标注「夹具来源」。

**验收**：夹具解析结果稳定；与真实来源在时间线上可区分。

#### FR-06 统一事件模型与增量同步

[[TABLE:表 3-9 事件类型]]
| 类型 | 关键字段 | 用途 |
|---|---|---|
| SessionStart | sessionId、agent、workspace、时间 | 会话索引 |
| Prompt | 文本、角色、时间 | 目标与纠偏识别 |
| Thinking | 文本摘要引用 | 决策辅助（不默认展示全文） |
| ToolCall | 工具名、参数摘要、时间 | 统计与证据 |
| ToolResult | 成功/失败、输出摘要 | 环境事实与失败尝试 |
| Edit | 文件路径、变更摘要 | 文件热点与习惯 |
| Correction | 原文、类别、置信度 | 经验提炼 |
| Unknown | 原始类型与引用 | 兼容未知格式 |

- 每条事件带 provenance：agent、sessionId、源文件、行号、时间戳、工作区；
- 增量同步使用文件偏移/哈希游标；
- 同一事件重复导入时按稳定指纹去重；
- 损坏行跳过并记录，不中断整体。

**验收**：增量导入两次结果一致；损坏行被记录；provenance 完整。

#### FR-07 脱敏与导入预览

- 识别并替换：API Key、令牌、邮箱、绝对用户路径、可能的密码字段；
- 导入前展示脱敏前后对照与命中统计；
- 规则可编辑，按项目保存；
- 脱敏在事件入库前完成；原始日志不被复制。

**验收**：夹具中的密钥与邮箱被替换；预览可见；关闭脱敏需显式确认。

### 3.2.8 可用性与增强需求

#### FR-24 实时采集适配器（P1）

- 为支持 hooks 的 agent（Qoder、Claude Code）提供可选插件：SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop；
- hook 只发送脱敏后的事件到本地，不发送原始日志与密钥；
- 默认不安装；未安装时回退到日志解析；
- 插件失败不影响 agent 正常使用。

**验收**：安装后新会话在 2 秒内出现在时间线；卸载后回退日志解析；错误不阻塞 agent。

#### FR-25 全局搜索（P1）

- 搜索范围：会话标题、事件文本、候选陈述、档案条目、交接简报；
- 支持按 agent、项目、类别、时间过滤；
- 结果展示来源与证据定位；点击跳转到对应界面。

**验收**：固定夹具的关键词召回正确；过滤器联动；无结果有空状态。

#### FR-26 首次使用引导与演示数据（P0）

- 首次启动提供三步引导：注册工作区 → 脱敏预览 → 生成第一份交接；
- 提供内置演示工作区（夹具会话），可一键体验完整链路；
- 引导可跳过，可再次打开；演示数据可删除。

**验收**：新用户在 5 分钟内完成首次交接；演示数据不写入用户真实工作区。

#### FR-27 长任务进度与取消（P0）

- 导入、提取、统计等长任务显示进度、当前步骤与预计剩余；
- 支持取消；取消后已提交的数据保持一致，不产生半成品；
- 失败可重试，游标不丢失。

**验收**：100MB 日志导入时进度可见、取消可用；取消后重试结果正确。

#### FR-28 会话-任务关联（P0）

- 任务可关联一个或多个会话（可跨 agent）；
- 支持手动选择、解除关联；
- P1 支持从会话标题/首条目标自动建议任务；
- 任务上下文包只使用关联会话与工作区档案。

**验收**：同一任务的会话可跨 Qoder 与夹具 agent；解除关联后上下文包更新。

#### FR-29 审查与写入撤销（P1）

- 审核操作可撤销（恢复到上一档案版本）；
- 写入前自动备份目标文件；支持从备份恢复；
- 撤销与恢复均写入审计日志。

**验收**：撤销接受后档案回到上一版本；文件恢复后与备份一致。

#### FR-30 跨工作区总览（P1）

- 在总览页按注册工作区聚合统计；
- 聚合在读取时计算，不建立中心化数据库；
- 支持按 agent、时间、项目筛选。

**验收**：多个工作区指标正确汇总；单工作区删除后总览同步更新。

#### FR-31 启动命令与打开工作区（P0）

- 派工完成后生成目标 agent 的启动命令（可复制）；
- 支持打开工作区文件夹；
- 不自动启动 agent、不控制其界面。

**验收**：不同 agent 的启动命令正确；打开目录与应用内路径一致。

| 编号 | 类别 | 需求 | 验收方式 |
|---|---|---|---|
| NFR-01 | 性能 | 首次扫描 100MB 日志 ≤ 15 秒；增量 ≤ 2 秒；界面操作 ≤ 200ms | 基准脚本 + 计时 |

| NFR-07 | 兼容性 | 生成符合 AGENTS.md / CLAUDE.md 约定；不覆盖非受管内容 | 黄金文件测试 |
| NFR-08 | 标准 | 统一术语；图表编号；需求-设计-测试追踪 | 文档评审 |
| NFR-09 | 安全 | 提取内容视为不可信；注入加分隔符；剥离控制字符；禁止自动执行 | 安全测试 + 代码审查 |
| NFR-10 | 可访问性 | 键盘可达、焦点可见、对比度达标；关键操作不依赖鼠标 | 可用性走查 |

补充说明：

- **性能**以本机 16GB 内存、SSD 为基准；超过阈值需在报告中说明；
- **可靠性**要求所有写入先写临时文件再原子替换，失败时保留原文件；
- **可用性**要求关键操作有说明，危险操作二次确认；
- **兼容性**要求受管块标记稳定，格式变化时向后兼容读取。

## 3.4 系统模型

### 3.4.1 场景

**S1 首次建档**：开发者注册 `SofteareEnjineer` 工作区，系统识别 git 仓库，发现 Qoder 会话与 Antigravity 摘要，展示脱敏预览，导入完成。

**S2 提炼习惯**：系统从真实会话中识别「优先 pnpm」「产物名保留版本号」等候选，展示证据与置信度；开发者逐条审核，接受两条、忽略一条。

**S3 换班交接**：开发者选择「交接给 Antigravity」，勾选任务状态、决策、失败尝试与环境，预览简报，确认写入 AGENTS.md 与 HANDOFF.md；系统记录交接。

**S4 复盘统计**：开发者查看最近 30 天的跨 agent 会话数、工具失败率与纠偏次数，发现某类命令反复失败，回到档案补充禁用项。

**S5 隐私删除**：开发者删除某个实验项目的数据，确认后事件、候选、档案与交接记录全部清除。

### 3.4.3 用例详述

#### UC-02 导入与刷新会话

- **参与者**：开发者
- **前置条件**：工作区已注册；日志目录可读
- **触发**：点击「刷新」或监听发现新会话
- **主流程**：
  1. 系统调用适配器发现日志源并识别格式；
  2. 展示脱敏预览与命中统计；
  3. 开发者确认导入；
  4. 解析事件、写入事件库、更新会话索引；
  5. 展示导入结果与失败行数。
- **异常**：格式无法识别 → 标记为未知来源；脱敏命中过多 → 提示调整规则；磁盘只读 → 报错并保留游标。
- **后置条件**：事件可查询；时间线更新；原始日志未被修改。

#### UC-05 审核候选

- **参与者**：开发者
- **前置条件**：已生成候选
- **主流程**：
  1. 收件箱按置信度排序展示候选；
  2. 开发者打开一条，查看陈述、证据、置信度；
  3. 选择接受、改写、合并或忽略；
  4. 接受/改写后生成档案变更与新版本；
  5. 记录审计日志。
- **异常**：证据源被删除 → 标记证据失效；冲突候选 → 提示人工选择。
- **后置条件**：档案内容与版本更新；候选状态更新。

#### UC-08 写入与注入

- **参与者**：开发者、文件系统
- **前置条件**：档案已有已接受条目；交接简报已生成
- **主流程**：
  1. 选择目标 agent 与文件；
  2. 系统计算受管块新内容并展示 diff；
  3. 开发者确认；
  4. 系统原子写入，更新文件哈希；
  5. 记录写入结果与交接状态。
- **异常**：文件被占用 → 重试/取消；受管块被手工修改 → 冲突提示；磁盘错误 → 原文件保留。
- **后置条件**：文件内容符合受管块约定；交接状态为 Written。

#### UC-10 查看统计

- **参与者**：开发者
- **前置条件**：已导入事件
- **主流程**：
  1. 选择项目与时间范围；
  2. 系统计算指标；
  3. 展示 KPI、趋势、分布与 Top 列表；
  4. 点击指标下钻到会话或事件。
- **异常**：数据为空 → 空状态；计算超时 → 后台任务与进度提示。
- **后置条件**：无状态变更。

## 3.5 数据与隐私需求

[[TABLE:表 3-15 数据分类]]
| 数据 | 存储位置 | 保留策略 |
|---|---|---|
| 原始日志 | 原目录，只读 | 不复制、不移动 |
| 事件与证据引用 | 应用数据目录 SQLite | 随项目删除 |
| 候选与档案 | SQLite + 导出文件 | 版本保留，可回滚 |
| 交接记录 | SQLite + 工作区 HANDOFF.md | 按保留期归档 |
| 设置与脱敏规则 | SQLite | 随应用删除 |

隐私要求：

- 不发起网络请求；不包含遥测；
- 脱敏在入库前执行；导出默认脱敏；
- 密钥、令牌、邮箱、绝对路径不得出现在档案与简报中；
- 删除项目时级联删除事件、候选、档案版本与交接记录；
- 用户可随时查看数据目录并手动备份。

## 3.6 假设、依赖与约束

- 会话日志由各 agent 在本地生成，格式可能变化；本系统通过适配器与指纹应对；
- Qoder JSONL 为本机主要真实来源；Antigravity 仅提供摘要；Claude Code 使用夹具；
- 目标 agent 读取工作区文件的能力取决于其自身实现；本系统不保证所有 agent 都读取 AGENTS.md/CLAUDE.md；
- 系统运行于 Linux/Windows 桌面，需具备工作区与日志目录的读写权限；
- 不依赖网络与外部服务；不依赖模型推理。
